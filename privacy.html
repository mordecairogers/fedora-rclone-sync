Fedora Rclone Sync

Privacy policy

This policy describes the owner's personal rclone configuration for local-first Google Drive synchronization. It covers authorized use of the setup, including synchronization when enabled by the owner.

Last updated: November 2, 2026

Data accessed and purpose

With the owner's Google authorization, rclone accesses Google Drive file and folder names, identifiers, directory structure, file contents, sizes, timestamps, checksums and other metadata needed to discover folders, verify transfers and synchronize selected files.

Read/write Drive access is requested to work with files that already exist in the owner's account. The permission is broader than the selected synchronization folders. Local configuration determines the folders used. The setup is for personal file synchronization, integrity checks, conflict preservation and backups.

Processing and storage

Rclone runs locally and exchanges data directly with Google's services. Selected files, local backups, synchronization state and operational logs are stored on the owner's computers or storage they explicitly select. Synced cloud copies and any configured cloud backup versions remain in the owner's Google Drive account.

OAuth client credentials, access tokens and refresh tokens are stored in protected local configuration files outside the synchronized vaults and this website. They are not published with the website. Operational logs may contain file names, paths and error information; authorization tokens and secrets must not be included in those logs.

Sharing and use of Google data

The configuration does not sell Google user data, use it for advertising, send it to an AI model for training, or provide it to a separate application backend. Data is transferred to Google's services as required for the owner's requested synchronization. Any additional destination or sharing would require a separate decision by the owner and an updated disclosure.

Fedora Rclone Sync's use and transfer of information received from Google APIs will adhere to the Google API Services User Data Policy, including its Limited Use requirements.

Retention and deletion

Local and cloud file copies are retained until the owner removes them through their file-management or synchronization workflow. Backups and preserved conflict versions are retained until the owner deliberately removes them; deleting a working file may leave copies in backups or Google Drive Trash. Removing authorization does not automatically erase existing file copies or backups.

To remove locally stored credentials, the owner can remove the relevant rclone remote or its protected token configuration. Copies on other devices and any credential backups must be handled separately.

Control and revocation

The owner chooses which folders to synchronize and may stop local synchronization jobs at any time. Google account access can be revoked through Google Account connections. Revocation prevents future authorized requests, but does not remove files already stored.

This website

This site publishes informational HTML and CSS only. It does not ask for Google credentials, receive Drive data, set application cookies, or run analytics. GitHub Pages, the website host, may process visitor connection information such as IP addresses and request logs under the GitHub Privacy Statement.

Contact and policy changes

For questions about this personal setup or its data practices, use the support email displayed on the Google authorization screen. This policy will be updated if the configuration's data practices change.
